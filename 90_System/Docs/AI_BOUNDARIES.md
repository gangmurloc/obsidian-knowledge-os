# AI Boundaries

## Permission Model

| Zone | Permission | Rules |
| --- | --- | --- |
| `30_Resources/Sources/` | READ | Source notes are evidence records. AI may analyze and link to them but may not silently rewrite them. |
| `30_Resources/AI-Wiki/` | READ + WRITE | AI may create and revise derived notes while preserving provenance and the data contract. |
| `30_Resources/Knowledge/` | READ + SUGGEST | No automatic body edits, moves, merges, status changes, or metadata rewrites. |
| `10_Projects/` | READ + SUGGEST | Suggestions are separate from the project note until accepted by a human. |
| `20_Areas/` | READ + SUGGEST | Suggestions are separate from the area note until accepted by a human. |
| `40_Archives/` | READ | Do not reactivate, move, edit, or delete archived material automatically. |

Paths not listed above are read-only by default. Ingestion automation may create new captures in `00_Inbox/`, and governance tooling may write dry-run reports to `90_System/Reports/`, but neither permission allows destructive changes.

## Prohibited Automatic Changes

AI must not automatically:

- edit the body of any note with `origin: me`
- assign or infer `knowledge_status: understood`
- assign or infer `knowledge_status: applied`
- create, rewrite, merge, or promote a user's Idea
- create, rewrite, merge, or promote a user's Decision
- combine external-source text, AI synthesis, and human-owned knowledge into one ownership layer
- set `human_verified: true`
- delete notes or assets
- perform bulk rename, bulk move, or inferred PARA classification
- store credentials in Markdown, prompts, logs, or generated reports
- send vault content to an external LLM API in version 1

## Local AI Rule

Version 1 uses a self-hosted Ollama model for chat and generation and calls it only through a loopback endpoint. Local embedding models are allowed. Any external provider setting must remain disabled. If inference is unavailable, stop and report the blocker rather than falling back to a cloud API, another endpoint, or another port.

The LLM runtime is Ollama on the user's own lab GPU server. Ollama is bound to `127.0.0.1` on that server and is never exposed to the network. The desktop reaches it only through an SSH local port forward that the user opens (`localhost:11435` to the server's `127.0.0.1:11434`). Automation never opens the tunnel and never accepts a remote host or IP address as `base_url`. The default model is `qwen3.5:27b`; the limits designed for a 4B model (1,024 output tokens, `think: false`, `temperature: 0`, one JSON repair, one concept per chunk, 12 concepts per Source) are retained.

The only vault data that leaves the desktop is the content of LLM requests: Source chunks for extraction, the model's own malformed response for JSON repair, and candidate summaries for curation. PDF ingestion, preprocessing, chunking, deduplication, role assignment, the quality gate, and every file write stay on the desktop. The lab server is user-owned infrastructure, not an external LLM API, so the prohibition on external LLM APIs is unchanged.

The lab GPU is shared. Every request carries a bounded `keep_alive`, and a run that made at least one LLM call sends one unload request when it ends so the model does not stay loaded.

## Suggestion Protocol

For Knowledge, Projects, and Areas, AI suggestions must be returned to the user or written as a clearly labeled proposal under `90_System/Reports/`. A proposal must identify:

- the target note
- the exact proposed change
- the reason for the change
- supporting source links
- whether the proposal affects metadata, links, or body text

Suggestions are never treated as accepted merely because they were generated.

## AI-Wiki Write Protocol

Before writing an AI-Wiki note, the agent must:

1. Verify that every source is under `30_Resources/Sources/`.
2. Use the properties defined in [[DATA_CONTRACT]].
3. Distinguish sourced claims from inference.
4. Add or update `## Provenance` without removing previous valid source references.
5. Default `human_verified` to `false`.
6. Show a dry-run for multi-note operations.

## Stop Conditions

Stop and request human direction when ownership is ambiguous, a requested change crosses zones, a source cannot be traced, a move would break links, or a task would require deletion or external LLM access.
